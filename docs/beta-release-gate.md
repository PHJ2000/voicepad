# beta 종료 기준과 정식 릴리즈 게이트

이 문서는 Voicepad가 `beta`를 끝내고 `정식 release`로 넘어가도 되는지 판단하는 기준입니다.
기능이 더 많아졌는지보다, 설치와 실행이 안정적이고 사용자가 스스로 복구할 수 있는지에 초점을 둡니다.

## 이 문서를 쓰는 시점

- 새 beta를 내기 직전
- 정식 release 후보를 판단할 때
- 큰 구조 변경 이후 배포 위험을 다시 점검할 때

## beta 종료 체크리스트

### 1. 기본 배포 자산

- `Voicepad-win64.zip`이 최신 `main` 기준으로 생성된다.
- 압축 해제 후 `run_codex_hotkeys.bat`와 `run_codex_dictation.bat` 둘 다 실행된다.
- `README.md`의 파일명과 실제 배포 자산명이 일치한다.

### 2. 첫 실행 경험

- 사용자가 `README.md`만 보고 설치와 실행을 따라갈 수 있다.
- 첫 실행 시 설정, 로그, 기록 파일 위치를 문서에서 바로 찾을 수 있다.
- `--doctor` 또는 앱 내 `Doctor`로 환경 점검이 가능하다.
- 첫 실행 실패 시 최소한 로그 수집 경로와 점검 순서를 안내할 수 있다.

### 3. 핵심 입력 시나리오

- 터미널 입력창에서 짧은 문장 입력이 안정적으로 된다.
- 브라우저 입력창에서 기본 입력이 된다.
- 메신저 계열 앱에서 기본 입력 또는 붙여넣기 흐름이 된다.
- 시스템 UI 계열 입력창에서 치명적 오작동 없이 동작한다.
- 항상 듣기와 수동 입력이 둘 다 기본 흐름에서 회귀 없이 동작한다.

### 4. 안정성

- `run_release_smoke.ps1`가 통과한다.
- `unittest`가 모두 녹색이다.
- 패키징이 성공하고 실행 파일이 실제로 생성된다.
- 치명 버그가 열린 상태로 남아 있지 않다.

### 5. 운영성과 복구 가능성

- 공유용 로그 변환 흐름이 문서화되어 있다.
- 문제 제보 시 필요한 로그 위치를 문서에서 찾을 수 있다.
- 알려진 제한사항이 있다면 릴리즈 노트에 적을 수 있을 정도로 정리돼 있다.

## 정식 릴리즈 게이트

아래 항목은 beta 종료보다 더 엄격하게 모두 충족되어야 합니다.

- 최근 beta에서 설치 불가, 실행 불가, 입력 완전 불가 같은 치명 이슈가 재현되지 않았다.
- 대표 시나리오 검증이 최소 한 번 이상 다시 수행되었다.
  - 터미널
  - 브라우저
  - 메신저
  - 시스템 UI
- 첫 실행 점검 흐름과 문제 해결 가이드가 `README.md`에서 끊기지 않는다.
- 릴리즈 자산, 버전 표기, 릴리즈 노트가 서로 모순되지 않는다.
- 정식 릴리즈 이후 바로 막아야 할 known blocker가 없다.

## 아직 정식 release로 보면 안 되는 신호

- beta 사용자가 설치 단계에서 자주 막힌다.
- 마이크 장치 인식이나 입력 타겟 판정이 환경별로 크게 흔들린다.
- 로그 없이 문제를 재구성하기 어렵다.
- 실행은 되지만 “어디에 입력될지” 예측이 어렵다.
- 릴리즈 노트에 적어야 할 known issue가 너무 많다.

## 릴리즈 판정 문구 예시

### beta 유지

- 핵심 기능은 동작하지만 설치/입력 안정성 피드백이 더 필요함
- prerelease 유지, 정식 release 보류

### 정식 release 가능

- 기본 설치/실행/입력/복구 흐름이 안정적
- 대표 시나리오와 스모크 테스트 통과
- 정식 release 진행 가능
